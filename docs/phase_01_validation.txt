PHASE 1 - REAL ML ENGINE VALIDATION

Status: PASSED on 2026-08-09.

Features and logic
- Pure, deterministic Faker-based generator core with normal, scan, bruteforce, and breach modes.
- Fixed dataset timestamps make feature extraction and quality metrics reproducible across processes.
- Runtime-shaped labeled records; generator_mode is ground truth and is_anomaly derives from it.
- Shared per-record feature schema: failed_login_count, status_code, route_frequency,
  response_time, error_frequency, request_rate, user_id, ip_frequency.
- PyOD Isolation Forest, One-Class SVM, and LOF models with a normalized PyOD average ensemble.
- Completion-audit correction (2026-08-10): ensemble now calls PyOD combination.average through
  its open-source combo dependency; normalization bounds and threshold are learned from training data
  and saved in the artifact rather than recalculated from each runtime batch.
- Rule-vs-ML evaluation uses rule_baseline_predictions from the same feature_engine rows as all models.
- Versioned joblib artifact stored below ignored instance/models/.
- Stratified 70/30 held-out evaluation and rule-vs-model metrics table.

Concept notes
- A training split fits model parameters; a held-out evaluation split measures behavior on unseen rows.
- Precision is the confirmed-anomaly share of predictions; recall is the detected share of true anomalies.
- F1 is their harmonic mean. False-positive rate measures normal rows incorrectly flagged.
- Matching training/runtime features prevents a model from learning signals unavailable in production.
